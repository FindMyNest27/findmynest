## Compact Rules (auto-resolved per phase)

### Supabase
- Treat `anon` key as public — security MUST live in RLS and Edge Functions, not in client.
- Every sensitive Edge Function MUST validate `Authorization: Bearer <jwt>` and ownership by `auth.uid()`.
- Never trust email/IDs sent from client; derive from JWT claims.
- Tokens MUST NOT live in `localStorage`; prefer `httpOnly` cookies or short-lived `sessionStorage`.
- RLS MUST be enabled per table and validated with cross-user deny tests.

### GitHub Actions
- Prefer SFTP/FTPS over plain FTP for deploys; rotate secrets after any pipeline change.
- Pin actions to commit SHA when handling secrets.
- Mask secrets in logs; never echo tokens or API keys.

### Security review
- For every `innerHTML` with dynamic data → require `esc()` or `textContent` replacement.
- Validate CSP without `'unsafe-inline'` in `script-src` once inline handlers are removed.
- Confirm no `localStorage.setItem` for tokens (`access_token`, `refresh_token`, `recovery`).
- Confirm `Authorization: Bearer` on every fetch to Edge Functions or sensitive REST endpoints.

### Pre-commit
- Block staged diff if it reintroduces: raw `innerHTML` with `${...}` interpolation, token in `localStorage`, inline `onclick=` on new code, plain FTP in CI.
